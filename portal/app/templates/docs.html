AIaaS API

An OpenAI-compatible API for {{ settings.model }}, an open-weight model served with vLLM on an on-demand GPU. If your code already talks to the OpenAI API, change the base URL and the key and it works here.

Base URL {{ base_url }}
Model {{ settings.model }}

Quickstart

  1. Create an account (you need the invite code from Team 5).
  2. Open API keys and create a key. It is shown once: copy it.
  3. Send a request. Replace sk-YOUR-KEY with your key.

curl

{% call code('ex-curl', 'bash') %}curl {{ base_url }}/chat/completions \ -H "Authorization: Bearer sk-YOUR-KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "{{ settings.model }}", "messages": [{"role": "user", "content": "Say hello"}] }'{% endcall %}

Python

Install the official SDK with pip install openai.

{% call code('ex-python', 'python') %}from openai import OpenAI client = OpenAI( base_url="{{ base_url }}", api_key="sk-YOUR-KEY", ) response = client.chat.completions.create( model="{{ settings.model }}", messages=[{"role": "user", "content": "Say hello"}], ) print(response.choices[0].message.content){% endcall %}

JavaScript

Install the official SDK with npm install openai.

{% call code('ex-js', 'javascript') %}import OpenAI from "openai"; const client = new OpenAI({ baseURL: "{{ base_url }}", apiKey: "sk-YOUR-KEY", }); const response = await client.chat.completions.create({ model: "{{ settings.model }}", messages: [{ role: "user", content: "Say hello" }], }); console.log(response.choices[0].message.content);{% endcall %}

Authentication

Send your key in the Authorization header of every request:

{% call code('ex-auth', 'http', 'header') %}Authorization: Bearer sk-YOUR-KEY{% endcall %}

A key is shown once, when you create it. Keep it out of source control. If one leaks, revoke it on the API keys page: it stops working at once. A missing, wrong or revoked key gets 401.

Endpoints

The public API has two routes. Anything else under /v1 returns 404.

MethodPathWhat it does
POST/v1/chat/completionsGenerate a reply to a conversation

Chat completions

POST /v1/chat/completions takes the same JSON body as the OpenAI API.

FieldTypeMeaning
modelstring, requiredUse {{ settings.model }}
messagesarray, requiredThe conversation: objects with role (system, user or assistant) and content
streambooleanSend the reply piece by piece as it is generated. Default false
temperaturenumber, 0 to 2Lower is more predictable, higher is more varied
max_tokensintegerUpper bound on generated tokens, reasoning included
top_p, stop, seedAs in the OpenAI API
reasoning_effortlow, medium, highHow long the model thinks before it answers

Streaming

With "stream": true the reply arrives as server-sent events: lines that start with data:, each holding a JSON chunk, ending with data: [DONE]. Use streaming for long answers so the connection stays active while the model writes.

{% call code('ex-stream-curl', 'bash') %}curl -N {{ base_url }}/chat/completions \ -H "Authorization: Bearer sk-YOUR-KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "{{ settings.model }}", "stream": true, "stream_options": {"include_usage": true}, "messages": [{"role": "user", "content": "Count to five"}] }'{% endcall %} {% call code('ex-stream-python', 'python') %}stream = client.chat.completions.create( model="{{ settings.model }}", messages=[{"role": "user", "content": "Count to five"}], stream=True, stream_options={"include_usage": True}, ) for chunk in stream: if chunk.choices and chunk.choices[0].delta.content: print(chunk.choices[0].delta.content, end="", flush=True) if chunk.usage: print("\n", chunk.usage.total_tokens, "tokens"){% endcall %}

With stream_options.include_usage the last chunk before [DONE] has an empty choices list and the usage totals.

Reasoning

{{ settings.model }} thinks before it answers. The thinking is returned separately from the answer, in reasoning_content: on the message for a normal response, and on delta while streaming (reasoning pieces come first, then content pieces). Reasoning tokens count toward completion_tokens and toward max_tokens, so leave room for them. Set reasoning_effort to low for quick answers.

Responses that are not streamed tell you where a key stands:

{% call code('ex-headers', 'http', 'response headers') %}x-ratelimit-api_key-limit-requests: {{ key_rpm_limit }} x-ratelimit-api_key-remaining-requests: {{ key_rpm_limit - 1 }} x-ratelimit-api_key-limit-tokens: {{ key_tpm_limit }} x-ratelimit-api_key-remaining-tokens: {{ key_tpm_limit - 81 }}{% endcall %}

Over a limit, the API answers 429 with a retry-after header (in seconds):

{% call code('ex-429', 'json') %}{ "error": { "message": "Rate limit exceeded for api_key: ... Limit type: requests. Current limit: {{ key_rpm_limit }}, Remaining: 0. ...", "type": "throttling_error", "code": "429" } }{% endcall %}

Wait and try again. The OpenAI SDKs do this for you; by hand it looks like this:

{% call code('ex-retry', 'python') %}import time import openai def ask(client, messages, attempts=4): for attempt in range(attempts): try: return client.chat.completions.create(model="{{ settings.model }}", messages=messages) except openai.RateLimitError as error: wait = float(error.response.headers.get("retry-after", 2 ** attempt)) time.sleep(wait) raise RuntimeError("still rate limited"){% endcall %}

Errors

Errors use the OpenAI shape: {"error": {"message", "type", "code"}}.

StatusTypeMeaningWhat to do
400invalid_request_errorThe body is malformed, for example messages is missingFix the request
401token_not_found_in_db, auth_errorThe key is missing, wrong or revokedCheck the key, or create a new one
403key_model_access_deniedThe model name is not one your key can useUse {{ settings.model }}
404invalid_request_errorUnknown routeUse one of the two routes above
429throttling_errorRate limit reachedWait for retry-after seconds
404, 500, or 429 with type all_deployments_in_cooldownThe model is offline: the GPU is not runningTry again later. The status badge on this site shows whether the model is online

Why is the model sometimes offline?

The GPU costs money while it runs, so it is started for sessions and shut down in between. Accounts, keys, usage and this site stay up the whole time.

Usage

Every request is metered per key: prompt tokens, completion tokens and whether it succeeded. Your Usage page shows the totals per day (in UTC) and per key, usually within 15 seconds of a request. Requests made in the playground are metered under a built-in key of their own.
